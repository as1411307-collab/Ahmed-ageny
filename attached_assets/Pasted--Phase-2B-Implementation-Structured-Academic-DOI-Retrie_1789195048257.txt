Structured Academic + DOI Retrieval MVP.

لا تغيّر:
- Tavily
- Search Fabric العام
- MY_FILES
- MCP
- Gemini
- Policy/HITL

الهدف:
إضافة Academic Layer مستقلة للبحث الأكاديمي المنظم،
مع DOI routing صحيح عبر أكثر من Registration Agency.

==================================================
1. ACADEMIC LAYER
==================================================

أنشئ module مستقل، مثل:

academic_search.py

لا تحشر AcademicResult داخل NormalizedSearchResult.

أنشئ:

AcademicProvider
AcademicResult
DOIResolver

==================================================
2. DOI NORMALIZATION
==================================================

أضف normalize_doi():

يدعم:
- 10.xxxx/...
- doi:10.xxxx/...
- https://doi.org/10.xxxx/...
- http://dx.doi.org/10.xxxx/...

ينظف:
- whitespace
- prefix
- URL wrapper

لا يغير suffix بشكل قد يفسد DOI.

احتفظ بـ:
original_doi
normalized_doi

==================================================
3. DOI REGISTRATION AGENCY ROUTING
==================================================

لا تفترض أن كل DOI هو Crossref.

حدد Registration Agency عبر مصدر رسمي مناسب:
- Crossref /works/{doi}/agency
أو
- DOI Foundation doiRA service

ثم:

Crossref DOI
→ Crossref metadata

DataCite DOI
→ DataCite Public REST API

Other/unknown RA
→ resolve DOI safely
→ return RA/landing URL if available
→ لا تخترع structured metadata

==================================================
4. CROSSREF
==================================================

استخدم REST API الرسمي مباشرة.

لا تضف SDK.

نفذ فقط:
- exact DOI lookup
- title lookup
- minimal metadata enrichment

أضف optional config:

CROSSREF_MAILTO

إذا موجود:
استخدم polite pool.

إذا غير موجود:
public access remains functional.

احترم:
- provider rate limits
- Retry-After
- bounded retries
- provider timeout

لا تخزن raw response دائمًا.

==================================================
5. DATACITE
==================================================

استخدم DataCite Public REST API فقط.

لا تحتاج API key.

في Phase 2B:
استخدم DataCite فقط لـ:
- exact DOI metadata lookup
- DataCite DOI resolution

لا تستخدمه كـgeneral academic search provider الآن.

لا تضف member credentials.

==================================================
6. OPENALEX
==================================================

استخدم OpenAlex API مباشرة عبر HTTP.

أضف optional:

OPENALEX_API_KEY

إذا غير موجود:
basic keyless access يظل ممكنًا ضمن حدوده الحالية.

إذا موجود:
استخدمه لرفع budget وتتبع الاستخدام.

لا تشترِ usage.
لا تفعل billing.

استخدم OpenAlex فقط عندما intent يحتاج:
- paper/topic discovery
- author resolution
- citations/references
- OA locations
- citation counts
- graph enrichment

لا تستخدم OpenAlex لكل DOI lookup إذا Crossref/DataCite كافيين.

==================================================

==================================================

title

لا تخزن references/citations graph كاملة داخل كل result.

اجلب graph edges on-demand فقط.

==================================================
8. ACADEMIC MERGE
==================================================

Identity priority:

1. normalized DOI
2. provider-native stable ID
3. title + author + publication year fallback

لا تستخدم URL dedupe الخاص بالويب لتحديد paper identity.

إذا metadata تعارضت:
- لا تخفِ التعارض
- احتفظ بـprovenance
- Crossref/DataCite record يفضل لحقول DOI registration الخاصة به
- OpenAlex يفضل للgraph/citation/OA enrichment

لا توجد قاعدة واحدة تفضل provider واحد لكل الحقول.

==================================================
9. ROUTING
==================================================

DOI intent:
→ DOI Resolver
→ provider responsible for DOI
→ OpenAlex enrichment فقط عند الحاجة

Exact title:
→ Crossref search
→ OpenAlex if ambiguity/enrichment needed

Author/topic:
→ OpenAlex

Citations/references:
→ OpenAlex

Latest research:
→ OpenAlex date-filtered results
→ Tavily only if current web/publisher context is useful

Generic non-academic:
→ current web_search
→ لا تستخدم Academic Layer
