==================================================
4. IMMUTABILITY
==================================================

بعد إنشاء source version:

- لا overwrite للbytes.
- لا mutation داخل نفس version.
- أي محتوى جديد = source version/source ID جديد وفق model المشروع.
- SHA-256 يحسب من original bytes الفعلية.

إذا تم رفع نفس bytes مرة أخرى:
يمكن deduplicate physical storage داخليًا إن كان آمنًا،
لكن authorization/source records تبقى صحيحة ومستقلة.

لا تجعل deduplication تكشف وجود ملفات لمستخدم آخر.


==================================================
5. ATOMIC INGESTION
==================================================

مسار upload الجديد يجب أن يكون منطقيًا:

1. authenticate owner
2. validate file type/size
3. stream original bytes
4. calculate SHA-256
5. persist immutable blob
6. create source metadata
7. run extraction/chunking
8. attach every chunk/extraction record to source_id + source SHA-256
9. commit successful ingestion state

إذا فشل التخزين قبل metadata:
لا تنشئ source صالحًا.

إذا تم حفظ blob ثم فشلت metadata:
نفّذ cleanup/compensation وفق backend الحالي.

إذا فشلت extraction:
الأصل يبقى محفوظًا،
لكن extraction_status يعكس الفشل.

لا تعتبر extraction failure فقدانًا للمصدر الأصلي.
