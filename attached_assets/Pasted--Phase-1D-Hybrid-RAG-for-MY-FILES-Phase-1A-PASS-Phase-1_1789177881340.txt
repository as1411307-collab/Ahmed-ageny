==================================================
1. PGVECTOR
==================================================

فعّل pgvector داخل PostgreSQL إذا كان متاحًا:

CREATE EXTENSION IF NOT EXISTS vector;

لا تضف Qdrant أو أي vector database أخرى.

أضف embedding column إلى document_chunks.

لا تحذف FTS الحالي.

==================================================
2. EMBEDDING PROVIDER ABSTRACTION
==================================================

أنشئ interface بسيط:

EmbeddingProvider
- embed_documents(texts)
- embed_query(text)
- model_name
- dimension
- status

لا تربط schema باسم نموذج ثابت.

ابدأ بمزود embedding محلي خفيف ومناسب للعربية والإنجليزية.

الأولوية:
multilingual-e5-small

قبل اعتماده:
- اختبر أنه يعمل فعليًا على موارد Replit الحالية
- سجّل memory usage التقريبي وlatency
- لا تفترض أنه مناسب فقط لأنه صغير

إذا فشل بسبب الموارد:
- لا تنتقل تلقائيًا إلى cloud embedding
- report RESOURCE_LIMIT
- لا ترسل محتوى الملفات إلى Gemini/Cohere/OpenAI بدون إذن

==================================================
3. DOCUMENT INGESTION
==================================================

عند رفع ملف جديد:

extract
→ chunk
→ FTS indexing
→ local embeddings
→ store embedding

إذا فشل embedding:
- احتفظ بالملف وFTS
- document status لا يصبح fully_indexed
- استخدم status واضح مثل:
  fts_ready
  embedding_failed
  ready

لا تقل إن vector indexing نجح إذا لم ينجح.

==================================================
4. VECTOR SEARCH
==================================================

أضف vector retrieval داخل search_my_files.

احصل على:
- top results من FTS
- top results من vector search

لا تعتمد على vector search وحده.

==================================================
5. RRF FUSION
==================================================

ادمج نتائج:

FTS
+
Vector

باستخدام Reciprocal Rank Fusion.

اجعل RRF constant configurable.

لا تستخدم provider scores مباشرة كأنها على نفس المقياس.

==================================================
6. RERANKING
==================================================

أضف reranking بسيط بعد RRF.

في MVP:
- لا تضف موديل reranker ثقيل إذا كان يضغط موارد Replit
- ابدأ بقواعد قابلة للقياس:
  exact term match
  filename relevance
  title/heading match
  chunk proximity if available

جهز interface لاحقًا لـML reranker، لكن لا تضف BGE reranker الآن إلا إذا benchmark الموارد نجح.

scope=MY_FILES:

user query

→ RRF
→ rerank
→ top chunks
→ Gemini final answer
→ citations
