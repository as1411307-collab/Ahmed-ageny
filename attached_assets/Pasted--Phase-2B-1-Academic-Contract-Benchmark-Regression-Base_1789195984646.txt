Academic Contract Benchmark + Regression Baseline.

الهدف:
تحويل Phase 2B من "الوظائف تعمل" إلى baseline قابل للقياس والمقارنة مستقبلًا.

==================================================
1. FIXED BENCHMARK DATASET
==================================================

أنشئ dataset ثابت داخل tests/fixtures/academic_benchmark/

يجب أن يحتوي على حالات حقيقية ومعروفة مسبقًا:

A. exact Crossref DOI
B. exact DataCite DOI
C. DOI بصيغة https://doi.org/
D. exact paper title
E. ambiguous title
F. author search
G. topic search
H. latest research
I. citation lookup
J. reference lookup
K. duplicate same paper from Crossref + OpenAlex
L. conflicting metadata
M. missing DOI
N. Arabic academic query
O. invalid DOI
P. no-result query

لكل fixture خزّن expected contract فقط:
- expected DOI
- expected title أو title pattern
- expected provider route
- expected merge behavior
- required fields
- whether enrichment is expected
- whether Tavily fallback is allowed

لا تخزن raw provider responses في fixtures.

==================================================
2. TEST TWO MODES
==================================================

MODE A — CONTRACT / DETERMINISTIC

يستخدم mocked/minimal provider responses
لا يعتمد على توفر APIs الحية.

الهدف:
regression tests مستقرة.

MODE B — LIVE SMOKE

عدد صغير فقط من الحالات:
- one Crossref DOI
- one DataCite DOI
- one OpenAlex author/topic
- one merged paper

إذا provider غير متاح أو rate-limited:
سجل LIVE_DEGRADED
ولا تفشل deterministic suite.

==================================================

==================================================
5. MERGE CONTRACT
==================================================

ثبت قواعد merge كاختبارات صريحة:

Identity:
1. normalized DOI
2. stable provider ID
3. title + author + year fallback

Field ownership:
- DOI-registration metadata:
  Crossref/DataCite source
- graph/citation/OA:
  OpenAlex source

إذا يوجد conflict:
- preserve provenance
- no silent overwrite

==================================================
6. NO-HALLUCINATION CONTRACT
==================================================

اختبر أن Academic Layer لا ينشئ:

- DOI غير موجود
- author ID غير موجود
- citation count غير موجود
- retraction status غير موثوق
- full-text URL غير موجود

missing data = null/unknown

وليس fabricated value.

==================================================
7. RETRACTION/CORRECTION SAFETY
==================================================

أضف fixture لحالة update/retraction إن أمكن.

- إذا provider يؤكد status → أظهره مع provenance
- إذا لا توجد بيانات → status=unknown

ممنوع:
"not retracted"
فقط لأن provider لم يرجع update.
