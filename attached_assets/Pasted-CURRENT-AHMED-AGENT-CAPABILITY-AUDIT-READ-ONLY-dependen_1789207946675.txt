CURRENT AHMED AGENT CAPABILITY AUDIT — READ ONLY

هذه مراجعة فقط.
ممنوع تعديل أي ملف أو dependency أو secret أو database schema.
ممنوع إضافة أي capability جديدة.

الهدف:
تحديد ما يستطيع Ahmed Agent runtime نفسه فعله فعليًا الآن، وفصل ذلك تمامًا عن قدرات Replit Agent/Workspace.

اعتبر server.py هو نقطة البداية، ثم تتبع runtime call graph الحقيقي.

لكل Capability اكتشفها، أعطني:

1. Capability name
2. ملفات التنفيذ
3. Runtime entry point
4. هل هي:
   - REGISTERED_WITH_AGENT
   - INTERNAL_ONLY
   - MCP_PUBLIC
   - HTTP_ENDPOINT
   - DORMANT
   - TEST_ONLY
   - REPLIT_AGENT_ONLY
5. ما الـprovider أو الخدمة التي تعتمد عليها
6. هل تحتاج Secret
7. هل الـSecret موجود/configured أم لا
8. هل هناك live end-to-end proof
9. آخر اختبار live معروف
10. هل توجد fallback path
11. هل تحفظ بيانات
12. ما الذي تحفظه بالضبط
13. هل ترسل بيانات إلى external provider
14. resource cost:
    - startup RAM
    - background processes
    - external API calls
15. dependencies المستخدمة فعليًا
16. duplicate/overlapping capability إن وجدت

==================================================
A. RUNTIME MAP
==================================================

ابدأ من:
server.py

تتبع فقط المسارات التي يمكن الوصول إليها فعليًا أثناء التشغيل.

أخرج:

User request
→ HTTP route
→ AgentCore
→ registered tool
→ provider/client
→ external service
→ returned result

لا تعتبر وجود function أو module دليلاً على أنها مستخدمة.
