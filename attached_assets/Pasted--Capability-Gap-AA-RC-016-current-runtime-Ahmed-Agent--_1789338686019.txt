التصميم المطلوب:

أولاً: أنشئ طبقة داخلية صغيرة للقراءة الآمنة للأدلة إذا لم توجد آلية مناسبة بالفعل.

هذه الطبقة ليست Tool عامة للـAgent.

وظيفتها فقط:
- قراءة ملفات محددة مسبقاً.
- تثبيت القراءة داخل project root.
- canonical path validation.
- منع path traversal.
- منع القراءة خارج allowlist.
- عدم تنفيذ shell commands.
- عدم الكتابة أو التعديل.
- عدم الوصول للشبكة.
- عدم قراءة .env أو secrets أو credentials.
- عدم إعادة محتوى الملفات كاملاً للموديل إذا لم يكن ضرورياً.
- إعادة الأدلة المطلوبة فقط مع file citation / line evidence قدر الإمكان.

لا تبنِ generic project_file_access.
لا تسمح للموديل بتمرير arbitrary filesystem path.

ثانياً: أضف AgentCore tool واحدة فقط باسم:

inspect_runtime_evidence

ويفضّل ألا تستقبل أي filesystem path من المستخدم أو الموديل.

الـallowlist لهذه capability يجب أن يكون ضيقاً ومخصصاً لإثبات runtime، وأساسه:

- server.py
- pyproject.toml
- .replit

يمكن إضافة runtime/config file آخر فقط إذا أثبت فحص المشروع أنه ضروري فعلاً لتحديد entrypoint الحالي، ويجب ذكر سبب إضافته في التقرير النهائي.

الأداة يجب أن تستخرج أدلة منظمة، لا أن تفترض النتيجة مسبقاً.

أريد ناتجاً منظماً شبيهاً بهذا المفهوم:

status:
- verified
- partial
- unverified

runtime evidence:
- language
- language version
- active entrypoint
- HTTP framework
- MCP presence
- server/runtime command
- configured port
- evidence references

لكل claim:
- اسم الملف.
- السطر أو النطاق إن أمكن.
- الدليل الذي يثبت claim.
- verified/unverified.

مهم:
لا تكتب في الكود أن النتيجة يجب أن تكون Python لمجرد أننا نعرف ذلك الآن.
الأداة يجب أن تستنتج النتيجة من الملفات الفعلية.
إذا كانت الأدلة ناقصة أو متعارضة، أعد partial أو unverified ولا تخمّن.
